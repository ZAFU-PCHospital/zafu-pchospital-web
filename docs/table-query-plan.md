# 表格查询统一方案（issue #214）

## 目标与已确认范围

本方案依据 issue 正文、两条评论及负责人本轮确认实施。目标是让常用后台查询遵循同一套操作规则，查询真实全量数据，并保持权限、隐私和原有业务顺序。

- 成员、维修、招募、邀请码、审计五个分页列表完成排序、快捷筛选、高级条件、计数、重置与可分享状态。
- 分类、技能保留业务拖动顺序和既有编辑/启停，只统一计数及清除能力说明；没有查询条件时清除入口禁用。
- 活动管理、接待看板及详情内嵌表列入能力清单，本轮保留专用交互。
- 维修、报名导出跟随列表筛选和排序，保留原列、权限、超限拒绝和审计，不导出统计结果。

## 对原建议的修正

1. `lastReviewedAt` 本来已通过 `JoinApplicationView` 进入列表，它是填写的面试时间。独立增加派生的 `approvedAt`，取首次通过审核记录的服务端创建时间；补记备注不改变首次时间，历史缺失显示“—”。不新增存储列或伪造回填。
2. 不为每个字段强加统计。默认计数来自已有分页总数；高级面板仅提供有限枚举分组，不新增平均审核耗时、任意求和或高基数个人信息分组。
3. 不照搬原预览的上一页/下一页，保留已部署的连续加载。每次 20 条，服务端上限 100，排序/筛选变化回到第一页。
4. 不把全部输入写 URL。只恢复受控排序、日期和枚举；姓名、账号、学号、批次等文本只存在当前页面，刷新/回退不恢复文本。
5. 清除查询与恢复列宽分开。用户清条件时不丢列宽偏好，也不改写管理员拖动顺序；不新增列显隐体系。

## 实现与真实消费者

- `AdminTable` 的既有三态排序箭头、`aria-sort` 和行渲染继续复用。
- 五个面板使用 `AdminTableQuery`/`useTableQuery`；高级条件复用 `AdminFilterDialog`、草稿转换和 `AdminModal`。常用字段在外，高级条件/完整排序/分组收进同一个弹层，窄屏仍可排序。
- `useAdminList` 统一由查询签名触发，去掉页面与 hook 的重复首屏入口。新条件取消旧请求、丢弃迟到页，连续加载单飞；刷新/失败保留已渲染内容。刷新期间不操作旧选择，失败计数明确标为上次结果。
- HTTP 解析继续复用 `list-query`/`list-filter`。排序映射集中到小型白名单函数，各领域仍拥有自己的筛选谓词与权限，不创建跨领域查询平台。
- 成员 Repository、维修 Query Service、JoinApplication Service、InviteCode Service、AuditLog Service 与对应管理 Route 同步贯通；成员/维修原调用方兼容可选新增字段。
- 报名使用同一参数化谓词处理列表、计数、分组和导出。列表只读取 DTO 所需字段，通过时间复用既有审核索引；没有每行补查询或额外读取完整报名资料。
- 默认统计不增加查询；选择分组才在同一 HTTP 响应增加 `meta.summary`。邀请码派生状态沿用同一 `now` 和原 SQL 谓词，逐项串行计数，避免五个额外并发连接。
- 能力清单从七张表格 spec 和前后端共用白名单生成，包含复合/派生列的例外及原因，使用 `pnpm table:capabilities` 检查漂移，CI 在安装依赖后自动执行。

## 安全、兼容与取舍

原认证、门禁、Service 权限、审核/建档、邀请码兑换、账号发放、出勤及接待写操作不变。统计不提供成员身份/联系方式分组；维修分组要求审核权限。

成功与失败继续采用统一信封，五个管理列表禁止共享缓存。搜索词和新增文本条件值不进入业务审计。共用表单使用 POST 兜底，脚本接管前禁用，防止浏览器原生 GET 提交泄露文本；受控草稿同步避免通过重挂载表单丢焦点。

排序默认值不变，并补稳定 ID 兜底；空值遵循 GreatSQL 原生规则。日期条件按上海自然日含结束日，维修 DATE 列维持日历日口径。维修默认隐藏草稿，明确选择草稿才纳入。成员多值标签、维修聚合等不支持的能力明确列出，不假装只排当前页。

分组及总数为实时查询结果，并非冻结数据库快照；并发写入时可能产生正常的跨语句变化。本轮不引入长事务、缓存平台或快照导出设施。

无 Schema/Migration、运行时依赖、新权限、新环境变量或部署改动。

- 浏览器仅验证代表性的新版招募表与高级面板：桌面/窄屏、双主题、Esc/滚动锁/焦点、清除及回退。截图为运行中的本地页面与明确标记的联调夹具，不是原线框预览或生产数据。

## 成员管理补齐导出（issue #232）

成员表沿用 #214 的列头三态排序、常用 / 高级筛选、全量分组与重置规则，列表工具栏新增
“导出当前结果 CSV / XLSX”，复用 `AdminTableExport`。导出取已应用条件和完整排序，
覆盖全部匹配成员，忽略分页、选择与分组；查询更新或失败期间禁用，失败保留条件供纠正。

成员 Repository 抽出共用筛选谓词，列表与导出同序；复用现有 CSV / XLSX 写入器、
20,000 行上限、权限和审计，不新增依赖 / Migration。QQ / 手机号保持脱敏，不导出邮箱。
公共契约仅追加成员导出输入 / 结果 / Service，消费者为成员导出 Service、Route 与测试，
既有列表接口、表格组件和其他页面兼容。验证覆盖前端查询透传、独立测试库中的分页 / 导出
一致性、CSV / XLSX 内容、隐私、权限、超限与审计失败；工具栏复用既有响应式布局。

## 后台列表筛选工具栏化（issue #274，P0）

P0 只确认方案与量化收益，不改业务代码。以下度量来自本机 `_test` 库夹具，低保真预览
仅用于方案评审、不随仓库保存；待维护者确认后再推进 P1 / P2。

### 问题

成员、维修、招募、邀请码、审计五个列表共用 `AdminTableQuery`。默认筛选区是一整块卡片：
每个字段竖排“标签 + 控件”，关键字输入框随可用宽度撑开，整块高 78.2px（招募在 1280
下换行到 99.2px），表格首行因此落在 214–643px；生效条件与排序 chip 再占一行，高度
增至 107.7px。高频操作只有“输入关键字并应用”，低频控件和竖排标签吃掉了首屏高度。

### 方案 A

- 工具栏化：`.admin-query` 内联字段，标签与控件同行；关键字固定 16rem，其余快捷字段
  7rem；应用 / 高级筛选 / 重置组成操作组靠右。统计、导出与分页位置不变。
- 生效条件独立成行：快捷条件与排序 chip 同区展示并逐个移除；没有条件时该行不占高度。
- 高级筛选入口常驻，文案由“高级筛选与统计”缩短为“高级筛选”，点击仍打开既有
  `AdminFilterDialog`；重置常驻，不清除列宽偏好。
- 小于 760px：字段整行堆叠，控件全宽、触控高度 46px；操作组换行；chips 单行横滑
  （44px），不产生页面横向溢出。
- 样式只作用于 `.admin-query`：`.admin-filters` 仍被维修操作面板与导出面板使用，
  不直接改其公共样式。
