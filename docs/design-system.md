# Design System

> 本文件是浙江农林大学电脑医院官网的**视觉唯一来源**。
> 所有页面必须遵守本文件。任何页面都不得自行发明品牌色、字体层级、圆角、阴影或按钮样式。
>
> 设计来源：本文件自身。早期用于比对的基准 Demo 已在架构整理中移除，
> 其视觉取值已逐值固化于此与 `globals.css`。
> 工程落地：`src/app/globals.css`（令牌 + 基础层 + 组件层）。

---

## 0. 使用方式

| 你想做的事           | 应该怎么做                                                            |
| -------------------- | --------------------------------------------------------------------- |
| 用品牌色 / 文字色    | 使用 Tailwind 工具类，如 `text-accent`、`bg-surface-1`、`border-line` |
| 用间距节奏           | 使用 `p-s-4`、`gap-s-5`、`py-s-sec` 等（`s-1` ~ `s-9`、`s-sec`）      |
| 用圆角               | 使用 `rounded-base` / `rounded-mid` / `rounded-pill`                  |
| 用缓动               | 使用 `ease-quart`、`ease-expo`、`ease-in`、`ease-io`                  |
| 写页面区块           | 用 `components/ui/Section.tsx`，不要自己写 `padding-block`            |
| 写按钮               | 用 `components/ui/Button.tsx`，不要新建第二套按钮                     |
| 需要新的稳定视觉模式 | 先在 `globals.css` 的组件层补充，并同步更新本文件                     |

**判断标准**：如果你写了一个新的十六进制颜色、新的 `border-radius` 数值或新的字号，就说明你在脱离设计系统。

## 1. Colors

> **本节描述的是「深色模式」所对应的主题 `black-yellow`。**
> 站点现在有两套主题：语义令牌的名称完全相同，取值不同，
> 由 `<html data-theme>` 决定。两套取值与完整主题架构见 **第 9 节**。
>
> ⚠️ 组件一律只使用语义令牌（`var(--accent)` 等），**不要写死本节里的色值** ——
> 写死之后切到另一个模式就会出现颜色冲突或看不见的文字。

基调：**工业极简 · 深色石墨 + 单一信号黄强调色**。
所有中性色统一带 **95° 微暖色相**，与信号黄同源，避免灰得发蓝。

调色板刻意只保留**一个强调色**。新增第二种强调色需要先经过设计确认。

| 令牌      | 值                    | Tailwind     | 用途                       |

### 1.4 强调色（唯一）

安全标识黄的语义是**「这是重点 / 这是可操作项」**，不是装饰色。

| 令牌            | 值                           | Tailwind                    | 用途                            |
| --------------- | ---------------------------- | --------------------------- | ------------------------------- |
| `--accent`      | `oklch(85% 0.175 99)`        | `text-accent` / `bg-accent` | 强调、编号、图标高亮            |
| `--accent-deep` | `oklch(70% 0.155 97)`        | `text-accent-deep`          | 强调色的深色变体（标记文字）    |
| `--accent-on`   | `oklch(17% 0.03 99)`         | `text-accent-on`            | **强调色底上的文字色**          |
| `--accent-wash` | `oklch(85% 0.175 99 / 0.1)`  | `bg-accent-wash`            | 提示框底色、ghost 按钮 hover 底 |
| `--accent-line` | `oklch(85% 0.175 99 / 0.34)` | `border-accent-line`        | 强调描边                        |

**对比度规则**：任何「强调色底 + 文字」的组合必须使用 `--accent-on`，不得使用 `--ink`。

### 1.5 语义色

设计基准中**没有** Success / Warning / Danger 三色，现在也没有。

`/join` 的新社员登记表是站点第一个带校验的界面，它同样不引入语义色：

- 必填与格式约束交给**浏览器原生约束校验**（`required` / `pattern` / `maxLength`）；
- 被拒绝的字段只用唯一的强调色标出：描边 `--accent`、说明文字 `--accent-deep`，
  语义仍然是「这一项需要你处理」，与 1.4 节的强调色语义一致；
- 提交成功**不使用 `.notice`**，改用中性 `--surface-1` 面板（见 4.6）。

后续阶段（报修、备案、评价）引入完整的状态反馈时，**必须先在这里补充语义色定义**，不得由各页面自行挑选红色或绿色。补充时要求：

- 与现有色板同色相体系（或明确说明为何需要不同色相）；
- 文字与底色组合满足 WCAG AA；
- 同时给出深色底下的可用变体。

## 2. Typography

字体栈：

- `--font-latin` → `font-latin`：`Archivo`（可变字体，含 `wght` 100–900 与 `wdth` 62%–125% 双轴）+ 回退
- `--font-sans` → `font-sans`：`Archivo` + 中文栈（PingFang SC / HarmonyOS Sans SC / MiSans / Microsoft YaHei / Noto Sans SC）

字体文件：`public/fonts/archivo-latin-wdth.woff2`，`font-display: swap`。

> 关键约定：**Archivo 通过 `font-stretch` 调节字宽**，这是该设计语言的识别特征。
> 大写标签通常用 `font-stretch: 116%–125%` + `letter-spacing: 0.14em–0.3em`。
> 不要用其他字体替代，也不要用 `transform: scaleX()` 模拟字宽。

**加载顺序与回退（2026-09 加载优化）**：

1. `layout.tsx` 里 `<link rel="preload" as="font" type="font/woff2" crossorigin>`：不预加载的话，
   浏览器要等 CSS 解析、布局完成、发现真的用到了才去取（实测 Slow 4G 下 +663ms 才发起、
   +1538ms 才到）。`crossorigin` 不能省，否则会变成两次下载；
2. 字体栈里紧跟 `Archivo` 的是一个**度量对齐**的回退面 `Archivo Fallback`
   （`src: local("Arial")` + `size-adjust` / `ascent-override` / `descent-override`）：
   它的行盒与宽度和 Archivo 逐像素一致（实测 100px 下都是 109px 行盒、646.7px 宽），
   因此字体替换时**不会重排**。数字是量出来的，改字体或改字号层级时要重新量
   （方法写在 `globals.css` 的注释里）；
3. `/fonts/*` 由 `next.config.ts` 发 `immutable`：字体不带内容哈希，
   **换字体文件必须换文件名**，否则老用户不会再来取。

> 仍未消除的一处：Archivo 的 `wdth` 轴是静态回退字体模仿不了的（Arial 没有宽度轴，
> 而 `size-adjust` 是等比缩放，放大宽度会连字高一起放大）。因此 `font-stretch` 的
> 展示级文字在字体到位的一瞬间仍会有宽度差 —— 首页 CLS 从 0.173 降到 0.162 就卡在这里。
> 要么接受，要么把它改成 `font-display: block`（没有替换就没有位移，代价是慢网络下
> 首屏拉丁文字晚 0.4s 出现）。这是设计取舍，改动前先确认。

### 2.1 字号层级

音阶为 **1.333 完美四度**。正文固定 `rem`，展示级使用 `clamp()` 流体。

| 层级      | 令牌        | 值                               | Tailwind         | 用途                  |
| --------- | ----------- | -------------------------------- | ---------------- | --------------------- |
| Micro     | `--t-micro` | `0.6875rem`                      | `text-micro`     | 等宽大写标签、编号    |
| XS        | `--t-xs`    | `0.75rem`                        | `text-xs`        | 小标签、页脚          |
| SM        | `--t-sm`    | `0.8125rem`                      | `text-sm`        | 按钮文字              |
| Base      | `--t-base`  | `1rem`                           | `text-base`      | 正文（`body` 默认）   |
| Display 3 | `--t-lg`    | `clamp(1.25rem, 1.6vw, 1.5rem)`  | `text-display-3` | `.lead` 引导段        |
| Display 2 | `--t-xl`    | `clamp(1.75rem, 3.4vw, 2.75rem)` | `text-display-2` | 移动端索引大标题      |
| Display 1 | `--t-2xl`   | `clamp(2.25rem, 4.6vw, 3.75rem)` | `text-display-1` | `.sec-title` 区块标题 |
| Hero      | `--t-hero`  | `clamp(3.4rem, 12.5vw, 9.5rem)`  | `text-hero`      | 首页主标题            |

**不要**在页面里直接写 `font-size: 28px` 这类固定值。需要新层级时先在这里加一行。

| 类           | 用途                                                                             |
| ------------ | -------------------------------------------------------------------------------- |
| `.band`      | 常规区块：`padding-block: var(--s-sec)` + 底部分隔线（`Section variant="band"`） |

### 3.4 响应式断点

设计基准只用两个断点，Tailwind 的 `md:` / `lg:` 已对齐：

| 断点 | 值       | 变化                                                          |
| ---- | -------- | ------------------------------------------------------------- |
| `md` | `760px`  | 首页 Hero / 关于 / 文档区块由单列变两列；服务条目状态标签归位 |
| `lg` | `1100px` | 左侧索引栏出现，移动端顶栏隐藏，`body` 让出 `--rail` 宽度     |

`@media (max-width: 759px)` 的移动端专属规则：服务条目状态标签换行、读数面板压成一行、Hero 水印字号放大。

> `md` 与 `lg` 覆盖了 Tailwind 默认值（768 / 1024）。这是刻意的：
> 设计系统只承认 760 与 1100 两个断点，页面不要使用 `sm:` / `xl:` 另开一套。

### 3.5 横向溢出

`body` 已设置 `overflow-x: hidden`，但**这不是用来兜底的**。
新增内容必须自行保证不溢出：长英文串要能断行，宽表格要包一层可横向滚动的容器。

- 桌面（≥1100px）显示左侧固定索引栏：品牌方块 + 竖排编号导航 + 底部徽标。

- 两套表现**不重复实现**，都由 `Header` 输出，导航项来自 `src/config/navigation.ts`。
- 当前页通过 `aria-current="page"` 标记，样式为 `--accent` 文字 + 左侧 2px 竖条。

### 4.4 按钮的具体规则

- `solid`：信号黄底 + `--accent-on` 文字。**每个页面最多一个**，用于该页最重要的行动点。
- `outline`：默认形态，透明底 + `--line-strong` 描边，hover 时黄色自下而上填充。
- `ghost`：无边框文字按钮，hover 时下划线从左展开。用于次级动作。
- 三者共用一个「hover 填充」机制（`::before` 的 `scaleY`），不要为某个按钮单独写 hover。
- 最小高度 `46px`，保证移动端可点面积。

### 4.5 提示框 `.notice` 规则

信号黄描边 + `--accent-wash` 淡底，**只用于「须知 / 风险 / 待补充」这类需要用户注意的静态信息**。
不要用它做成就提示或成功反馈。

### 4.6 表单控件（`.signup` / `.field`）

第一阶段只有 `/join` 的新社员登记表用到表单，使用面还不够宽，因此**没有抽成
`components/ui/` 组件**，稳定的部分落在 `globals.css` 组件层；等第二个表单出现时再提升。

| 类                                         | 用途                                                                    |
| ------------------------------------------ | ----------------------------------------------------------------------- |
| `.signup` / `.signup__form`                | 登记区栅格（≥760px 两栏：表单 / 说明）与表单的纵向节奏                  |
| `.field` / `.field__label` / `.field__num` | 字段：两位编号 + 中文标签 + 必填标记                                    |
| `.field__input`                            | 输入框：`--line-strong` 描边、`--r-base` 圆角、最小高度 46px、字号 16px |
| `.field__hint`                             | 字段下方的格式说明（原生校验提示很简略，格式必须在这里讲清楚）          |
| `.signup__actions` / `.signup__status`     | 提交行与状态 / 失败提示                                                 |
| `.signup__done`                            | 提交完成后的确认面板（`--surface-1` 面板，**不是** `.notice`）          |

规则：

- 必填与格式约束**只有一份**，写在原生约束校验属性上（`src/config/join.ts` 的字段定义），
  页面不重复实现一套 JS 校验，也不自造错误提示样式。
- 控件边界一律 `--line-strong`（3:1）；输入框字号必须是 `--t-base`（16px），
  更小会让 iOS Safari 在聚焦时把整页放大。
- 提交成功**不用 `.notice`**（见 4.5），用中性面板 + 强调色标记。
- **提交后新插入的内容不要包 `.reveal`**：`SiteEffects` 只在挂载时收集一次 `.reveal`，
  后插入的元素永远拿不到 `.is-in`，会一直停在 `opacity: 0`。

### 4.7 后台构件（M6）

后台是密集型数据界面，新增的三个构件都**建立在既有视觉之上**，不引入新形态。

| 类                    | 用途                                                                            |
| --------------------- | ------------------------------------------------------------------------------- |
| `.admin-panel`        | 给 `.card` 补内边距与内部节奏（`gap: --s-5`）                                   |
| `.admin-panel__title` | 面板 / 窗口内部的标题（`--t-lg`），不要改用页头尺寸的 `.admin-workspace__title` |
| `.admin-modal`        | 详情窗口：全屏遮罩 + 居中窗口，内部独立滚动                                     |
| `.admin-toast`        | 操作成功反馈：顶部居中浮层，4 秒后自动消失                                      |
| `.admin-photos`       | 记录详情里的照片缩略图栅格（点击在新标签打开原图）                              |

规则：

- **`.card` 自身没有内边距**（`/docs` 的预览卡由 `.docpreview__bar` / `__body` 各自带 padding）。
  把表单直接放进 `<Card>` 会让标题与控件顶着左上角，看起来像「样式没加载出来的纯文本」。
  后台所有卡片式表单都要加 `.admin-panel`。
- 面板标题用 `.admin-panel__title`。`.admin-workspace__title` 是**页头**尺寸（`--t-xl`，
  最大 2.75rem），用在卡片里会让「新增分类」和页面标题一样大，层级就反了。
- `.admin-modal` 必须通过 `createPortal` 挂到 `document.body`：页面内容位于 `<main>` 的层叠
  上下文里（`main` 自带 `z-index`），不挂 body 的话桌面索引栏（`.rail`，80）与移动端顶栏
  （`.topbar`，85）会穿过遮罩浮在窗口上面。
- 遮罩用 `--bg-deep`（加深的底色）+ 92% 不透明度，**不加投影**（见 §5.2）。
- 窗口行为与移动端索引浮层同构：`role="dialog"` + `aria-modal` + `aria-labelledby`、
  `Esc` 关闭、打开时锁定 `body` 滚动、焦点落在窗口容器（`tabIndex={-1}`，读屏先朗读标题）、
  关闭后把焦点归还给触发按钮。窄屏（<760px）窗口铺满可用高度。
- 窗口内**不要再套第二层卡片**：各段之间用 `--line-soft` 细线分隔即可。
- **成功反馈走 `.admin-toast`，不要内联插一行文字**：内联的那行会把下面的表单/表格顶下去
  （页面高度一变，浏览器的滚动锚定还会跟着动），而且它不会自己消失，得等下一次操作覆盖。
  浮层是 `position: fixed`，完全不参与布局。
- 浮层只承载**一行的成功反馈**；错误（`role="alert"`）与「必须带走的信息」——初始密码、
  批量逐条失败明细、导出空结果诊断——仍然内联，那些不能自动消失。
- 浮层用**中性面板 + 强调色图标**（复用 `.card` 的描边与 `--surface-1`），
  **不能**改用 `.notice`：§4.5 规定 `.notice` 只用于须知 / 风险，不做成功反馈。
- 浮层图标按**语气**取，不是按成败取：`success`（做完一件事：保存 / 更新 / 启用 / 审核通过）
  用对勾 + `--accent-deep`；`neutral`（成功地把状态改成「关掉」：停用 / 禁用 / 退回 / 软删除）
  用叉 + `--ink-3`。两者都表示操作成功，因此**不用颜色区分** —— 本站只有一个强调色、
  也没有危险色令牌，结果由文案说清楚。
- 照片字节读不出来时（文件被清理、存储路径变更）显示 `.admin-photos__fallback` 占位，
  **不给「打开原图」链接** —— 那个 URL 只会返回一张 JSON 错误页。
- 浮层同样要 Portal 到 `document.body`：不挂 body 会被移动端顶栏（`.topbar`，85）盖住；
  `z-index: 100` 高于 `.admin-modal`（96），窗口内部触发的反馈也看得见。
  窄屏另加 `inset-block-start: 4.5rem` 让开固定顶栏。
- 「大号数字 + 小号单位」的指标卡（`.member-metric`）**单位只能出现一次**：
  数字用 `.member-metric__value`，单位用 `.member-metric__unit`；
  `config/member.ts` 的 `formatCount()` 返回的字符串自带「次」，两者不能叠加（会渲染成「1 次次」）。

**后台密度（只在 ≥760px 生效，集中在 globals.css 的「后台密度」一节）**

官网页面的尺⼨是给「呼吸感 + 触控面积」用的：`.btn` 46px、`.field__input` 46px / 16px 字号、
`.page-head` 上下 7–10rem 留白。管理台是密集数据界面，照搬的结果是一屏看不到 8 行记录、
每个控件都在抢注意力。因此后台单独覆写为：按钮 24px、输入框 28px / 13px、
表格行高约 34px、页头留白 16px、内容列铺满右侧可用宽度。**窄屏不参与**：
手指仍然需要 46px 的触控面积，`.field__input` 的 16px 还兼着「iOS Safari 聚焦不放大整页」。

**页脚**：`body` 是纵向 flex、`main` 吃掉剩余高度，所以内容不足一屏时（例如只有 8 行分类的
后台页）页脚仍然停在页面最底部，而不是紧跟内容浮到屏幕中间。
页脚自身是**落款**而不是内容区：上下内边距 `--s-4 / --s-5`，三段之间只留 `--s-3`
（一轮验收里它占了近 240px，顶上还跟着表格，看起来像页面正文）。
`.footer__note` **不设 `max-width`** —— 免责说明是一句完整的话，按 `ch` 限宽会让它在
一行只差二三十像素时硬折成两行；宽度够就一行读完，不够再自然换行。

规则补充：

- **交互不得改变页面格局。** 用户在点了什么之后，页面上已有元素的位置都不该变。
  具体做法：反馈用不占布局的浮层；「随状态出现」的元素用固定定位 + 渲染在内容**最后**的
  占位补留白；重载数据时保持已渲染内容（只有首次加载进 `loading`）。
  完整规则与三次实际踩坑见 `AGENTS.md` 的「交互不得夺走操控权」。
- 后台外壳（`.admin-shell`）渲染在 **layout** 而不是页面里：App Router 的 layout 在客户端
  导航之间保持挂载，切页时侧栏不重建、不闪。页面不再自己渲染导航。
- 导航预取**按意图触发**（悬停 / 聚焦 `router.prefetch`），不是挂载即全量预取：
  后者会一进后台并发拉 10 个页面，而且预取完成会让路由器重渲染当前页面 ——
  页面上的 `.reveal` 已被 `SiteEffects` 加上 `is-in`，于是 React 报 hydration 不匹配。
- **后台不做进场揭示**：`.reveal` 在 `.admin-shell` 内被中性化，`SiteEffects` 也跳过它。
  密集数据界面切页还等淡入属于装饰性动画（与「不加装饰性动画」同一条）。
- 列表取数用 `useAdminList` + `AdminListEnd`（往下滚动自动接下一页），
  不再有「上一页 / 下一页」；工具栏常驻，未选中时批量按钮置灰。
- **批量工具的标记只有一份**：`components/admin/AdminBatchTools.tsx`。
  结构固定为 `[全选] [已选择 N 项 / 未选择记录] │ [批量动作…] [取消选择]`，
  成员管理与维修审核两处共用，差异只是传进去的动作按钮。
  需要额外输入的批量动作（批量退回的原因）走**弹层**，不塞进顶栏 ——
  塞进去会把顶栏撑高，也会让两个列表的顶栏长得不一样。
- **拖动排序**（技能标签 / 故障分类）用 `components/admin/useRowDragSort.ts`：
  只有行首手柄 `draggable`（整行可拖会让表格里的文字选不中），拖动图示取整行，
  落点按目标行的**上半 / 下半**决定插到它之前还是之后（只判断「悬停哪一行」就没法拖到末尾）。
  指示线用绝对定位的伪元素画：`border` 会改行高（拖动时整表跳动），`box-shadow` 是禁止项。
  手柄同时是键盘用户按不动的控件，因此 `aria-hidden`，并保留每行的 ↑ ↓ 作为键盘 / 触屏路径
  （HTML5 拖放在触屏上不触发）。
- `.tagpicker` 的已选盒与候选行**两处都能操作**（点已选 = 取消），并且实时显示剩余额度；
  到上限后未选中的候选自动禁用，而不是静默忽略点击。
- 一次性凭据（初始密码 / 完整邀请码）仍然内联显示，不进浮层。

- **单元格只有一个字段值，且只有一行。** 昵称、维修时长这类「补充说明」跟在同一行
  （`.admin-cell__aside`，空值统一 `—`），**不要另起第二行小字**：一旦有第二行，
  行高就在 29px / 43px 之间摇摆，整张表参差不齐，而且「一个单元格 = 一个字段值」
  这件事失真 —— 后续做单元格就地编辑时，编辑对象就不统一了（第八轮验收）。
- **列宽交回使用者（Excel 式全局竖线）**：`.admin-table--resizable` 的表格用
  `useColumnResize` 算出每条列边界，在表格之上铺一层 `.admin-colgrid` 覆盖层，
  每条 `.admin-colline` **贯穿表头与所有行**，在整条线任何位置按下都能拖。
  宽度存 `localStorage`（键 `zafu-pchospital:admin-columns:<表>:v2`），首帧不读存储以免
  hydration 不匹配，挂载后再覆盖。四条配套约定，每条都对应一次实测：
  - **竖线跟着指针走，它右边的列整体平移，差额由最后一列吸收**（总和恒等于容器宽）。
    这是踩了两版才定下来的模型：
    ① 只改「被拖那一列」的宽度时，差额会被浏览器塞给没写死宽度的那一列 ——
    实测拖「技能标签」右边界 +120px，那一列确实 +120，但**左边缘同时左移 120**，
    右边缘与竖线一动不动（成员列从 165px 压到 45px），用户看到的是「拖了半天线不动、
    列却变形得厉害」→ 反馈「拖动距离被数倍放大」；
    ② 改成「相邻两列对冲（左 +Δ、右 −Δ）」方向对了但行程太短，实测只走了 44px 就顶住
    （右邻已经到 48px 下限），用户照样觉得拖不动。
    现在的模型：`新宽度 = 指针位置 − 该列左边缘`，1px 就是 1px，行程 = 最后一列宽 − 最小宽
    （默认 102px），反向拖回来原样还回去，而且**永远不会把表格撑出横向滚动条**。
  - **拖动期间不重渲染整张表**：`pointermove` 只改 `<col>` 与竖线的行内样式，
    `pointerup` 才落到 state 与 `localStorage`。之前每帧 `setState` 会重渲染 60 行 × 9 列，
    用户反馈「拉动特别卡」（实测：拖动 12 帧期间 tbody 的 MutationObserver 计数为 0）。
  - **竖线位置由列宽累加算出**，不再量 DOM（总宽恒定时两者等价，但省掉了
    `ResizeObserver` + `useLayoutEffect` 的来回测量；旧版还踩过「表格晚挂载 → 普通 ref
    是 null → 竖线一条都画不出来」）。
  - 命中区整个放在边界**左侧**（`translate: -100%`）：骑在边界上时右半边会被下一列盖住
    （单元格按顺序绘制），最右一列还会把表格撑出几像素。
  - 键盘：竖线可聚焦，←/→ 调 8px、`Shift` 加倍、`Home` 或双击恢复该列默认宽度。
  - **卡片布局（≤1099px）里竖线要收起来**：那时表格已经不是「列」了，
    竖线位置又是算出来的（不再依赖量 DOM），不收的话卡片上会飘着几条线。
- **行首是「手柄 + 序号」，不是复选框阵列**（飞书式），而且**与首列共用同一格**：
  平时显示序号（安静、便于口头沟通「第 12 行」），指针进入这一行或**键盘焦点可见地**
  落进来时换成复选框 —— 两者同尺寸同位置，用 `opacity` 互换，行高列宽都不动。
  - 序号原先单独占一列（56px），复选框右边缘到姓名之间横着 25px 空白，用户反馈
    「复选框到成员之间还是雷霆大宽度，和首列属性共享一个区域好了」——并进首列后
    只剩一个固定间距（实测 9.2px），行首还随首列一起被拖动列宽。
  - 显形条件必须用 `tr:has(:focus-visible)` 而**不能**用 `:focus-within`：
    鼠标点完复选框焦点会留在 input 上，`:focus-within` 把复选框一直钉在那里，
    取消勾选后也不退回序号（实测反馈）。
  - 复选框是**替换元素**，`inset: 0` 配固定宽高会被浏览器当成「左上定位、右边忽略」，
    于是压在盒子左上角；要 `margin: auto` 才能两轴居中（实测反馈）。
  - 六点手柄**与复选框同步出现**（用户要求「六面骰 icon 和复选框的出现是同步的」）：
    平时两者都 `opacity: 0`，指针进入这一行（或键盘焦点可见地落进来）时一起淡入 ——
    同一条过渡、同一个时长，实测过渡中途两者进度差为 0。手柄用 `opacity` 而不是
    `display` 隐藏，那 16px 始终占着位，出现时不会把姓名挤动。
  - **手柄拖动 = 调整这一行的位置**（用户要求「icon 的拖动调整单元行上下位置」）。
    实现复用 `useRowDragSort`（技能 / 分类拖动排序的同一套）：整行只有手柄 `draggable`，
    落点按目标行的上 / 下半判断，指示线是绝对定位伪元素（`border` 会改行高、`box-shadow`
    是禁止项）。拖动一次只发一个 `move` 请求，服务端整份重排 —— 一格一格上移要发 N 次。
  - **勾选多行后拖其中任意一行 = 整块一起移动**（用户要求「多个选中后无法一起拖动」），
    块内保持原有先后。两条配套约定：落点解析**跳过被移动的那几行**（否则鼠标必然先掠过
    块自己，落点会解析成「插到自己前面」= 原地不动，表现就是「拖不动」）；
    拖动中整块都标 `is-dragging`，用户能看出走的是哪几行。
  - **松手立即到位（乐观更新）**（用户要求「拖动不是立即响应修改的」）：排序规则收在
    `src/lib/list-order.ts` 的纯函数里，**客户端与服务端共用同一份**，界面松手先按它改本地
    顺序，再发请求；失败才回滚并报错。服务端写的就是同一套规则算出来的顺序，因此成功后
    **不再重新取列表**（重取只会让已看到的顺序再闪一次，还会把下翻出来的几页缩回第一页）。
    实测：松手到 DOM 顺序更新 ≈ 155ms，且发生在接口响应之前。三个可拖动的列表
    （成员 / 技能 / 分类）用同一份手感，不要只给其中一个加。
    手柄同时带 `role="button"` / `tabIndex` 与 ↑ ↓ 方向键：成员表没有操作列，
    键盘与触屏没有别的路可走（HTML5 拖放在触屏上不触发）。
  - 顺序是**服务端持久化的**（`member_profiles.sort_order`）：拖完刷新还在。
    第八轮曾把手柄做成「连续选中若干行」，第九轮按用户要求改成调整行位置 ——
    选择一段仍可用 `Shift` 点击，而「拖」这个手势只留一种含义，不会互相抢。
- **单元格一律左对齐 + 垂直居中，且行高唯一。** 第八轮撤掉了单元格里的第二行小字
  （`.admin-subline` 删除），第九轮又撤掉了「数字 / 日期右对齐」：表里混着文本列与数字列，
  右对齐只让这两列看起来被推出队列（用户反馈「加入时间为什么擅自改成右对齐，
  单元格都是左对齐 + 垂直居中好看」）。
  行高在第九轮实测出 40 行里混着 29px / 27px 两种，原因不是文案而是**标签比行框高**：
  技能 / 角色标签自报 21.7px（11px 文字 × 1.5 + 上下内边距 3.2 + 描边 2），
  正文行框只有 19.5px（13px × 1.5）。修法是让行框稳压标签一头
  （`.admin-table--resizable td { line-height: 1.75 }` = 22.75px），
  同时把标签自己的 `line-height` 钉回 1.5 —— 它是继承来的，行框一改高标签跟着长，
  永远追不上（压 `min-height` 没用：标签的高度是内容 + 描边撑出来的）。
- **内容比列宽长时，容器与每一项都要能收缩 + 自己裁。** `td` 有 `overflow: hidden`，
  但只裁它不够：子元素照样比父元素宽，浏览器仍会把差额算进 `.admin-table-wrap`
  的滚动宽度（实测：联系方式里的元素比容器宽 90px，表格明明铺满容器却多出 4~8px 横向滚动；
  bisect 到最后是**表头**那格 ——「联系方式」四个字 58px 挤进 54px 的列）。
  于是 `th`、`.admin-contacts` / `.admin-tags` 及其子项都设 `overflow: hidden` +
  `text-overflow: ellipsis`，多出来的字以省略号收尾（比在字符中间被切断好认）。
- **没有「吸附列」了。** 之前留一列宽度为 `null` 吸收剩余空间；现在由
  `useColumnResize` 保证**总和恒等于容器宽**（挂载与容器尺寸变化时差额给最后一列，
  容器比基准总宽还窄时整表等比缩），因此每一列都能拖，也不会在表格右侧留一条空带。

- **详情入口不占一整列**：成员表的「操作」列撤掉，改成悬浮整行时出现在**首列右端**的
  `.admin-peek` 小框（「查看」），点击打开详情窗口。`opacity` 而不是 `display`：
  它始终在布局里、始终可聚焦，Tab 到它时靠 `:focus-visible` 显形，不产生位移。
- **「查看」全场最多一个，跟着鼠标走**（用户要求「查看只跟着鼠标悬浮单元行的位置走，
  全场不会出现多个查看」）。三条规则配合：`tbody:hover tr:not(:hover) .admin-peek`
  先把非悬浮行的「查看」收起（权重刻意压过下面两条）、`tr:hover .admin-peek` 显示悬浮行、
  `.admin-peek:focus-visible` 让键盘 Tab 到它时仍看得见。
  **不要**写成 `tr:has(:focus-visible) .admin-peek`：焦点落在行里的复选框上时
  也会顺带点亮「查看」，那就又成了「鼠标没停在这行，却冒出一个查看」。
  列表里撤掉的功能（重置密码、禁用/启用）都还在详情窗口里，没有丢。
- **表格宽度要用来装信息，而不是留白。** 成员表原来只显示姓名 / 学号 / 班级 / 角色 /
  状态 / 维修数 / 联系方式，把「技能标签」「加入时间」（详情接口里早就有）留在详情窗口里，
  一屏 1080px 有一半是空的。第六轮验收把这两列搬进表格，并定下几条配套规则：
  班级截断 + `title`；技能标签**最多显示 2 枚**、其余收成 `+N`
  （3 枚会把这一列撑到 234px，整表在 1440px 下溢出 64px —— 实测后改回 2）。
- **列多到放不下时横向滚动，不要压缩列。** `.admin-table-wrap` 从 `overflow: hidden`
  改成 `overflow-x: auto`：压缩列宽的后果是行内 flex 组换行、行高翻倍，
  比横向滚一下糟得多。**1440px（内容列 1081px）实测必须放得下、不出滚动条**，
  1100–1400px 之间允许横向滚动（≤1099px 已经是卡片布局，不存在这个问题）。
- **后台没有页脚**：`body:has(.admin-shell) .footer { display: none }`。页脚的落款、
  备案号与文档来源说明属于公开站点；后台是登录后的工作台，这些信息没用还占高度。
  用 `:has()` 而不是在根 layout 判断路由 —— 根 layout 渲染 `<Footer/>` 时并不知道当前路由。
- **导航加载骨架必须与真实页面同构**：`app/admin/loading.tsx` 也要包
  `Section variant="page-head"` → `Container` → `.admin-workspace__content`。
  少一层会让骨架内容比真实页面高 16px、左边少一层内边距，载荷到达时整页跳一格
  （用户原话：「每次点不同页面都会抖一下，Admin Console 上方的空白高度突然小一下又恢复」）。
- **侧栏 sticky 偏移用 0**：`.admin-nav { inset-block-start: 0 }`。sticky 的位移受包含块高度
  限制，页面高时被顶到 16px、页面矮时夹回 0，切页时侧栏会跳 —— 视觉留白改由侧栏自身的
  `padding-block-start` 提供，与页面高度无关。
- **列表分页统一走 `useAdminList` + `AdminListEnd`**。批 1 在成员与维修管理里各写了一份
  22 行 JSX，批 2 又新增四个分页列表；六个列表的状态机（首次加载 / 追加 / 重载不清空）
  完全一致，因此收在一个 hook 里，写第二份分页逻辑就等于再造一批漂移点。
  列表末尾只写「已全部加载」，**不再重复顶栏已经写过的总数**。
- 只读的审计界面**只提供 `GET`**，界面上也没有编辑 / 删除入口：能改的审计等于没有审计。
- 「一次性凭据」（新建邀请码的完整明文、重置密码、初始密码）**不进浮层**：
  浮层 4 秒就消失，来不及抄。它们走内联区块并写明「只显示这一次」。
- 表格里的辅助信息用 `.repair-table__flags`（次级文字色，另起一行）承载，
  不要为了「一行放更多」而把字号压到 `--t-xs` 以下。

## 5. Radius / Border / Shadow

### 5.1 圆角

**单一 2px 基数**，工业感，刻意接近直角。

| 令牌       | 值      | Tailwind       | 用途                       |
| ---------- | ------- | -------------- | -------------------------- |
| `--r-base` | `2px`   | `rounded-base` | 按钮、标签、控件、序号方块 |
| `--r-mid`  | `4px`   | `rounded-mid`  | 面板、卡片、提示框         |
| `--r-full` | `999px` | `rounded-pill` | 圆点、滚动条（仅此两类）   |

**禁止**出现 `8px`、`12px`、`16px` 之类圆角。需要更大的面就用 `--r-mid`。

### 5.2 边框

统一 **1px**，颜色只用 `--line` / `--line-soft` / `--line-strong` / `--accent-line` 四个令牌。

- 区块之间：`1px solid var(--line-soft)`
- 面板边界：`1px solid var(--line)`
- 交互控件：`1px solid var(--line-strong)`（保证 3:1）
- 强调：`1px solid var(--accent-line)`

### 5.3 阴影

**设计基准不使用任何 `box-shadow`。**

层次完全由「边框 + 底色明度差」表达：

| 层级             | 表达方式                                                      |
| ---------------- | ------------------------------------------------------------- |
| 页面底           | `--bg`                                                        |
| 面板             | `--surface-1` + `--line` 边框                                 |
| 面板内的交互态   | `--surface-2`                                                 |
| 浮层（索引浮层） | `--bg-deep`（比底更深）+ 全屏遮罩                             |
| 详情窗口         | `--bg-deep` 遮罩（92%）+ `--surface-1` + `--line-strong` 窗口 |

禁止为「高级感」添加投影。需要浮层时用底色加深 + 全屏遮罩。

## 6. Motion

### 6.1 令牌

| -------------- | -------------------------------- | ---------------------- |
| `--ease-quart` | `cubic-bezier(0.25, 1, 0.5, 1)`  | 常规过渡（颜色、背景） |
| `--ease-expo`  | `cubic-bezier(0.16, 1, 0.3, 1)`  | 位移、展开、进场       |
| `--ease-in`    | `cubic-bezier(0.7, 0, 0.84, 0)`  | 退出                   |
| `--ease-io`    | `cubic-bezier(0.65, 0, 0.35, 1)` | 循环动效               |
| `--d-fast`     | `140ms`                          | 颜色、描边             |
| `--d-mid`      | `260ms`                          | 背景、常规过渡         |
| `--d-slow`     | `420ms`                          | 位移、下划线展开       |
| `--d-enter`    | `760ms`                          | 进场揭示               |
| `--d-theme`    | `560ms`                          | 主题切换               |

### 6.2 既有动画清单

设计基准已有、正式站点全部保留：

| 名称       | 位置                   | 说明                                                  |
| ---------- | ---------------------- | ----------------------------------------------------- |
| 进场揭示   | `.reveal`              | 进入视口上移 20px + 淡入，同级元素错位 70ms，只播一次 |
| 标题行进场 | `.hero__title .hl__in` | 从 `translateY(105%)` 上移，逐行错位 130ms            |
| 顶部进度线 | `.progress-line__bar`  | 优先 CSS 滚动时间轴（合成线程），JS 兜底              |
| 跑马灯     | `.ticker__track`       | 42s 线性无缝循环                                      |
| 区块走线   | `.sec-head__rule`      | 进入视口时从左展开 900ms                              |
| 按钮填充   | `.btn::before`         | hover 时 `scaleY(0) → 1`                              |
| 箭头下沉   | `.hero__scroll svg`    | 2.4s 循环的 `nudge`                                   |
| 索引浮层   | `.menu`                | `clip-path` 展开 + 子项逐个上浮                       |
| 指针准星   | `.reticle`             | 鼠标跟随，阻尼 0.22，仅在精确指针设备启用             |

### 6.3 禁止清单

不要为「高级感」增加以下内容：

- 大量粒子特效
- 复杂 3D 变换
- 新的鼠标跟随 / 光晕跟随特效（已有的准星是唯一一个）
- 大面积炫光、渐变光斑
- 每个组件各自一套动画体系

### 6.4 无障碍：减少动效

`prefers-reduced-motion: reduce` 时必须：

- 关闭所有进场揭示与循环动画
- 关闭指针准星
- `scroll-behavior` 回退为 `auto`
- 主题切换：令牌插值压成瞬时，落墨与按钮动画一并关闭（CSS 的 reduced-motion 段与 `playThemeShift()` 双重把关）

进度条是**功能性指示**而非装饰，保留其滚动驱动行为（`.progress-line__bar` 显式排除在全局 `animation-duration: 0.01ms` 之外）。

### 6.5 性能约定

- 动画只动 `transform` 与 `opacity`，不动 `width` / `height` / `top` / `left`。
- 滚动相关效果使用 `IntersectionObserver` 或 CSS 滚动时间轴，**不要监听 `scroll` 事件计算位置**。
- 站点级效果集中在 `SiteEffects` 一处挂载，不要在页面里各写一份监听。

> ⚠️ **进场揭示必须以 `pathname` 为依赖重新扫描，不能只在挂载时跑一次。**
>
> `.reveal` 的隐藏态来自 `html.js .reveal { opacity: 0 }`，只有 JS 补上 `.is-in`
> 才会显示。`SiteEffects` 挂在根布局上，**客户端路由切换时不会重新挂载**；
> 若只在挂载时 `querySelectorAll` 一次，新页面的 `.reveal` 永远拿不到 `.is-in` ——
> 表现为切页后主内容区整片空白、手动刷新才恢复（刷新能好，是因为整棵树重新挂载）。
>
> 因此 `SiteEffects` 里有两段 effect，职责必须分清：
>
> | 段落     | 依赖         | 放什么                                                       |
> | -------- | ------------ | ------------------------------------------------------------ |
> | 一次性段 | `[]`         | `html.js` 标记、顶部进度线、指针准星 —— 整站生命周期只跑一次 |
> | 换页段   | `[pathname]` | 进场揭示（重新扫描 + 观察）与它的兜底                        |
>
> **将来任何「与页面内容有关」的效果都要放进换页段。** 换页段里还有一道兜底：
> 宽限期后把「已进入视口却仍是隐藏态」的元素直接补上 `.is-in`，
> 保证内容在任何异常下都不会永久不可见；它的判定口径与观察器一致，
> 正常路径下不会提前揭示视口之外的元素。

### 6.6 主题切换动效

模式切换是本站唯一一处「全站同时变化」的动效，分三层，时长共用 `--d-theme`：

- **颜色**（承载：`<html>` 上的令牌）—— 用 `@property` 把颜色令牌注册成 `<color>`，再在 `<html>` 上对**令牌本身**声明 `transition`。
- **文字**（承载：`html.theme-shift`）—— 临时类触发 `theme-ink`：标题轻微下落归位 + 淡入。
- **控件**（承载：同上）—— 选中按钮的图标翻转归位 + 整体轻微上浮。

**为什么过渡声明在令牌上，而不是逐个元素**：站内不少视觉是令牌二次合成的 —— 索引栏的线性渐变、首页水印的 `-webkit-text-stroke`、准星的 `mix-blend-mode`。这些属性本身不可插值（渐变与混合模式没有中间态），但它们的**输入值**可以。只让令牌动，全站自动跟着平滑，新增组件也不必各自处理。

**为什么需要一个 JS 临时类**：纯 CSS 没有「属性变化时补播一次动画」的手段 —— `animation` 只在选择器**首次匹配**时启动，而切换模式改变的是 `aria-pressed`，不会重启动画。`src/lib/theme.ts` 的 `playThemeShift()` 负责加类、并按 CSS 上的 `--d-theme` 决定何时摘掉；时长只有这一个来源，JS 里不写死。

**注册范围的约束**（新增主题令牌时最容易踩）：

- 只注册**字面色值**的令牌。`--deco-grid-line: var(--line)`、`--rail-panel: var(--surface-1)` 这类**派生引用故意不注册** —— 它们每帧会重新解析被引用的令牌，天然跟随中间值；再注册一层反而让过渡叠加、出现滞后。
- `--t-page-title` 这类含视口单位的 `clamp()` **不能**注册：注册后的长度会被绝对化成 px，窗口缩放时不再重算，等于破坏响应式。
- `--deco-scan`（全屏扫描渐变，透明度仅 0.03~0.05）与 `--page-title-leading`（行高，属布局属性）**不注册，也因此不参与过渡**：它们不需要被插值，注册不会带来收益，只会多出一处容易被误加进过渡列表的口子。理由见 `globals.css` 对应注释。

> ⚠️ **不要用「给 `*` 挂颜色过渡」来优化这段动效。** 实测在软件渲染环境下它反而更慢：
> 每帧要给上千个元素逐个判定过渡状态，帧时间从 ~60ms 涨到 ~107ms。
> 令牌级写法只声明一处、覆盖全站，元素数量再涨也不增加声明成本。

**性能预期（实测记录，供后续排查对照）**：在**无 GPU 的软件渲染**环境（SwiftShader）下，1440×900 切换期间帧间隔约 23ms（≈43fps）；把视口缩到 600×400（像素面积约 1/5）后回到 21ms —— 帧成本随**像素填充量**缩放，说明瓶颈在光栅化，而不是样式重算（同一窗口内样式重算仅 97ms、布局 0.55ms，颜色仍是连续插值）。真实 GPU 环境这部分几乎不计，不要为此改动实现。

## 8. 变更流程

1. 判断是「一次性样式」还是「会复用的模式」。
2. 一次性 → 用现有工具类组合，不要新增令牌。
3. 会复用 → 在 `globals.css` 组件层补充 → 同步更新本文件 → 在 PR 描述里说明原因。
4. 涉及**新增颜色、新增字号层级、新增圆角数值**的改动，必须在 PR 中单独说明，不能混在功能改动里。

> 目标：任何人拉取代码后，只看本文件就能知道界面应该长什么样，
> 以及自己写的页面有没有跑偏。

## 9. Theme Architecture

### 9.1 三个概念

```text
Mode      用户能看到的开关        normal | dark
Theme     具体视觉方案            swiss-cobalt | black-yellow
Mapping   Mode → Theme            src/config/theme.ts 的 siteThemeConfig
```

界面**只暴露 Mode**。`Swiss Cobalt`、`Black Yellow` 这类主题名属于后台与文档，
不出现在任何页面文案里。

解析链路：

```text
用户点「深色」
      ↓
siteThemeConfig.dark                    ← 管理员配置层（未来改为数据库读取）
      ↓
"black-yellow"
      ↓
<html data-mode="dark" data-theme="black-yellow">
      ↓
CSS 主题层的语义令牌
      ↓
所有组件（组件不认识主题，只认识令牌）
```

**页面结构与主题视觉完全解耦。** 主题只决定颜色、圆角、边框、排版尺度、装饰强度；
不决定内容、区块顺序、Grid 主结构、路由、权限、数据或业务逻辑。
因此**永远不要**出现下面这种写法：

```tsx
// ❌ 禁止：为两个模式维护两套页面
if (theme === "normal") return <NormalAboutPage />;
return <DarkAboutPage />;
```

### 9.2 语义令牌

组件只使用语义令牌，不要判断当前是什么模式。

| 语义           | 令牌                                       | Tailwind                                                  |
| -------------- | ------------------------------------------ | --------------------------------------------------------- |
| 页面底色       | `--bg`                                     | `bg-bg`                                                   |
| 更深一层底     | `--bg-deep`                                | `bg-bg-deep`                                              |
| 面板 / 表面    | `--surface-1` … `--surface-3`              | `bg-surface-1` …                                          |
| 正文 / 标题    | `--ink`                                    | `text-ink`                                                |
| 次级正文       | `--ink-2`                                  | `text-ink-2`                                              |
| 说明文字       | `--ink-3`                                  | `text-ink-3`                                              |
| 元信息 / 标签  | `--ink-4`                                  | `text-ink-4`                                              |
| 强调（主色）   | `--accent`                                 | `text-accent` / `bg-accent`                               |
| 主色深色变体   | `--accent-deep`                            | `text-accent-deep`                                        |
| 主色底上的文字 | `--accent-on`                              | `text-accent-on`                                          |
| 主色淡底       | `--accent-wash`                            | `bg-accent-wash`                                          |
| 主色描边       | `--accent-line`                            | `border-accent-line`                                      |
| 描边           | `--line` / `--line-soft` / `--line-strong` | `border-line` / `border-line-soft` / `border-line-strong` |

**禁止**：

```css
color: #2457ff; /* ❌ 写死某个主题的具体色值 */
background: #ffd400; /* ❌ */
```

```tsx
theme === "dark" ? "#FFD400" : "#2457FF"; // ❌ 组件里判断主题再挑颜色
```

**应该**：

```css
color: var(--accent);
background: var(--bg);
border-color: var(--line);
```

判断标准：组件代码里出现任何一个具体色值，就是在脱离主题系统。

### 9.3 主题层的位置

色值的唯一来源是 `src/app/globals.css` 顶部的两段：

| 选择器                            | 内容                                                                               |
| --------------------------------- | ---------------------------------------------------------------------------------- |
| `:root`                           | 主题无关令牌 + **默认主题**（normal → `swiss-cobalt`）的语义色，同时作为无脚本兜底 |
| `html[data-theme="black-yellow"]` | 深色主题（dark）的语义色覆盖                                                       |

`src/config/theme.ts` **只登记主题身份与映射关系，不存放色值**。
两者的对应关系是「ThemeId ↔ `html[data-theme="<id>"]`」。

### 9.4 两套主题的实际取值

| 语义令牌        | normal / `swiss-cobalt` | dark / `black-yellow`        |
| --------------- | ----------------------- | ---------------------------- |
| `--bg`          | `#f5f5f2` 暖白纸面      | `oklch(14.5% 0.006 95)` 石墨 |
| `--bg-deep`     | `#edece7`               | `oklch(11.5% 0.006 95)`      |
| `--surface-1`   | `#ffffff`               | `oklch(18% 0.006 95)`        |
| `--surface-2`   | `#efeee9`               | `oklch(22% 0.007 95)`        |
| `--line`        | `#d8d8d4`               | `oklch(31% 0.008 95)`        |
| `--line-soft`   | `#e6e6e1`               | `oklch(23% 0.007 95)`        |
| `--line-strong` | `#8a8a85`               | `oklch(52% 0.009 95)`        |
| `--ink`         | `#171717` 炭黑          | `oklch(96% 0.008 95)`        |
| `--ink-2`       | `#3d3d3b`               | `oklch(82% 0.009 95)`        |
| `--ink-3`       | `#5f5f5d`               | `oklch(68% 0.009 95)`        |
| `--ink-4`       | `#70706e`               | `oklch(60% 0.009 95)`        |
| `--accent`      | `#2457ff` 钴蓝          | `oklch(85% 0.175 99)` 信号黄 |
| `--accent-deep` | `#1c44d6`               | `oklch(70% 0.155 97)`        |
| `--accent-on`   | `#ffffff`               | `oklch(17% 0.03 99)`         |
| `color-scheme`  | `light`                 | `dark`                       |

`swiss-cobalt` 取自实验分支 `style-about-editorial-test` 已验证的
「暖白 + 炭黑 + 钴蓝 · Swiss Editorial / Technical Editorial」方向。
其中 `--ink-3` / `--ink-4` 两档比实验原值（`#737373` / `#8f8f8b`）更深：
原值是按纯白 `#ffffff` 计算的，落在实际纸面 `#f5f5f2` 上只有 4.34:1 / 2.97:1，
达不到 AA，因此重新按实际底色配了一组（见 9.6）。

### 9.5 主题还能控制什么：视觉令牌

主题不只是颜色。`globals.css` 里另有一组可被主题覆盖的视觉令牌：

| 令牌                   | 用途                     | normal                  | dark                  |
| ---------------------- | ------------------------ | ----------------------- | --------------------- |
| `--r-frame`            | 图集 / 照片框圆角        | `0`（直角，接近印刷品） | `var(--r-mid)`        |
| `--deco-grid-line`     | 背景走线栅格的线色       | `var(--line)`           | `var(--line-soft)`    |
| `--deco-scan`          | 扫描质感带               | 钴蓝 5%                 | 信号黄 2.8%           |
| `--deco-watermark`     | 首页水印字形描边         | 钴蓝 17%                | 信号黄 16%            |
| `--deco-reticle-blend` | 指针准星的混合模式       | `multiply`              | `screen`              |
| `--rail-panel`         | 左侧索引栏面板的渐变起点 | `var(--surface-1)` 做亮 | `var(--bg-deep)` 做暗 |

页面内标题的字号、行高与字距属于信息层级，不随显示模式切换；模式只改变颜色、材质与装饰效果，避免相同内容在浅色/深色模式下发生布局跳动。

> `--deco-reticle-blend` 是个例子：准星原本写死 `mix-blend-mode: screen`，
> 这在深色底上成立、在暖白底上会让准星彻底看不见。装饰类取值必须同样令牌化。
>
> `--rail-panel` 是另一个例子：索引栏原本写死 `gradient(--bg-deep → --bg)`。
> 深色主题下面板比页面更深是成立的；但浅色主题里 `--ink-4` 在 `--bg-deep`
> 上只有 4.20:1，栏内导航文字会掉出 AA。**浅色主题必须把面板做亮，而不是做暗。**

**主题不控制**：区块顺序、Grid 主结构、DOM、交互、数据、路由、权限。
否则多主题会演变成多套网站。

主题**可以**调整 `--d-*` / `--ease-*` 动效令牌，但当前两套主题没有差异，
因此它们仍留在 `:root` 的主题无关段里。

### 9.6 对比度（实测）

两套取值按 WCAG 相对亮度公式算出的结果（正文门槛 4.5:1，控件边界 3:1）：

| 组合                                    | normal     | dark       |
| --------------------------------------- | ---------- | ---------- |
| `--ink` on `--bg`                       | 16.41:1 ✅ | 17.64:1 ✅ |
| `--ink-2` on `--bg`                     | 9.97:1 ✅  | 11.35:1 ✅ |
| `--ink-3` on `--bg`                     | 5.86:1 ✅  | 6.86:1 ✅  |
| `--ink-4` on `--bg`                     | 4.54:1 ✅  | 5.01:1 ✅  |
| `--ink-3` on `--bg-deep`（浮层 / 面板） | 5.41:1 ✅  | 7.06:1 ✅  |
| `--accent` on `--bg`                    | 4.95:1 ✅  | 12.60:1 ✅ |
| `--accent-on` on `--accent`             | 5.41:1 ✅  | 12.18:1 ✅ |
| `--accent-deep` on `--accent-wash`      | 6.13:1 ✅  | 6.48:1 ✅  |
| `--line-strong` on `--bg`（控件边界）   | 3.18:1 ✅  | 3.59:1 ✅  |

**边界规则（务必记住）**：`--ink-4` 只能用在 `--bg` 与 `--surface-1` 上。
它在更深的表面上会掉出 AA：

| 组合                       | normal    | dark      |
| -------------------------- | --------- | --------- |
| `--ink-4` on `--surface-2` | 4.27:1 ❌ | 4.36:1 ❌ |
| `--ink-4` on `--bg-deep`   | 4.20:1 ❌ | 5.16:1 ✅ |

所以：

- 落在 `--surface-2` / `--bg-deep` 上的文字，用 `--ink-3` 而不是 `--ink-4`
  （浮层底部标签、切换控件未选中项都按这条处理）。
- 浅色主题的深色面板（索引栏）通过 `--rail-panel` 改做亮，而不是靠加深文字补救。
- 强调色**底**（`--accent-wash`）上的文字用 `--accent-deep`，不要用 `--accent`：
  后者在淡底上只有 4.50:1，正好卡在门槛上。

> 上面的数字是实测值。改主题取值后在真实页面里复核渲染后的对比度，
> 注意把 oklch 等色彩空间先归一化成 sRGB —— 浏览器会把计算值原样序列化成
> `oklch(...)`，直接按 `rgb()` 解析会全部落空、静默跳过检查。

### 9.7 新增一个主题

1. 在 `src/config/theme.ts` 的 `themeRegistry` 登记 `{ id, name, mode, colorScheme, browserThemeColor }`。
2. 在 `globals.css` 主题层追加一段 `html[data-theme="<id>"]`，覆盖需要的语义色与视觉令牌。
3. 需要让用户看到它 → 改 `siteThemeConfig`（例如把 `normal` 指向新主题）。
4. 用 9.6 的方式复核对比度，并在 PR 中给出实测数字。

**页面代码一行都不用改。** 这正是把 Mode 与 Theme 分开的目的。

### 9.8 按主题取图（唯一的例外）

真实照片**不随主题换图**（深色模式最多允许极轻微的 brightness / contrast 调整）。
唯一的例外是二维码这类功能性图形：`/qq-group-qrcode-accent.png` 自带深色底，
放在暖白纸面上会像一块贴错位置的补丁。

处理方式：`src/config/site.ts` 的 `contactQr` 同时提供 `src`（黑底黄码版）
与 `srcLight`（浅底原色版），两个 `<img>` 都在服务端渲染，
由 `html[data-theme]` 决定显示哪一张。隐藏的那张是 `display:none`，
不进入无障碍树、也不会产生 hydration 分支。

`/join` 的 `joinSignupQr`（`src/config/join.ts`）按同一套处理：两版取自同一张
截图的同一区块，尺寸必须一致（`1044 × 1323`），否则切主题会引起布局跳动。

**除这类功能性图形外，不要为不同主题准备两套图片。**
