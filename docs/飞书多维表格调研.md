# 飞书多维表格（Lark Base）设计调研

> 用途：M6 后台「成员管理」表格的改造依据（第七轮验收要求「把详情里有价值的信息搬进表格，
> 后续向飞书多维表格的形态靠」）。调研由子任务完成，这里保留可直接使用的结论。
>
> **可信度标注**：`[A]` 官方截图 / 官方帮助译文直接读到；`[B]` 同类产品官方文档；
> `[C]` 未确认。**报告里不编造像素数字** —— 飞书帮助中心与开放平台文档都是前端渲染的 SPA，
> 正文需要内部签名才能取到，官方《Base 开放设计规范》需要登录，因此凡涉及具体像素，
> 要么注明「本项目实测值」，要么标 `[C]`。

## 1. 界面解剖（`[A]`）

先纠正一个常见误解：**左侧栏不是视图列表**。

- **左侧栏** = 「数据表 / 仪表盘 / 工作流」清单（顶部搜索框，底部「新建」区）。
- **视图** = 表格**上方**一排横向标签页（`任务状态看板 | 进展甘特图 | 按项目查看 | ＋`）。

| 分区       | 常驻 / 浮层 | 内容                                                                                                                                                                                       |
| ---------- | ----------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Base 顶栏  | 常驻        | 文件名 + 星标 + 保存状态；右侧分享 / 高级权限 / 自动化 / 通知 / `⋯` / 搜索 / `＋`                                                                                                          |
| 左侧栏     | 常驻        | 数据表 / 仪表盘 / 工作流清单 + 底部新建区                                                                                                                                                  |
| 视图标签条 | 常驻        | 视图名 + 类型图标、当前视图高亮、`＋新建视图`；可编辑者改动后出现「清除 / 保存」条                                                                                                         |
| 工具栏     | 常驻        | **左半（怎么看）**：添加记录 / 字段配置 / 视图配置 / 筛选 / 分组 / 排序 / 行高；**右半（拿去用）**：提醒 / 生成表单 / 分享视图 / 撤销 / 重做 / 搜索 / 评论。两半之间不画分隔线，靠间距分组 |
| 表头行     | 常驻        | 全选列 → 每列「字段类型图标 + 字段名」→ 最右一个 `＋`（新增字段）                                                                                                                          |
| 表格主体   | 常驻        | 行号列 → 值列；分组时插入分组行（`▼` + 组名 + 「N 条记录」）；整行选中时行外一圈强调色描边                                                                                                 |
| 表格底部   | 常驻        | 全宽 `＋` 行（新增记录）。Airtable / Notion / vika / Teable 另有**列汇总栏**；飞书是否有未确认 `[C]`                                                                                       |

**点击后是浮层还是抽屉**（关键）：

| 入口                                 | 形态                                                                                 | 证据  |
| ------------------------------------ | ------------------------------------------------------------------------------------ | ----- |
| 筛选 / 分组 / 排序 / 行高 / 视图配置 | 锚定在按钮下方的**下拉浮层**，表格不重排                                             | `[A]` |
| 字段编辑（双击列名）                 | **右侧抽屉**（约占视口 28%），左侧表格保持可见                                       | `[A]` |
| 记录详情                             | **右侧宽面板**（约占 60%），左上 `‹ ›` 上一条 / 下一条，标签页「详情 · 评论 · 历史」 | `[A]` |

## 2. 列宽 / 冻结 / 行高（`[A]` `[B]`）

- 列宽：手动拖列边界；首列（索引列）默认冻结，且**不能删除 / 移动 / 隐藏**。
- 冻结：「冻结至此字段」= 从索引列整段冻到该列，不支持单独取消某一列。
- 新增字段有 4 个入口：表格最右 `＋` / 字段配置面板 / 记录详情页底部 / 右键列名插入。
- 行高：飞书有《设置多维表格行高》一文，但**档位名与像素未确认** `[C]`；
  同类产品 Airtable 是 `Short / Medium / Tall / Extra Tall` 四档且同样不公布像素，
  Teable 是「短 / 中 / 高 / 超高」+ **表头字段名 1/2/3 行**独立档位。
  **行高是视图级设置**，改了不影响其他视图。
- 单元格**不支持居中**（飞书官方 FAQ 明说）。

## 3. 单元格类型与就地编辑（`[A]` `[B]`）

| 字段类型                                                    | 渲染                                | 交互                                                                                                               | 空值   |
| ----------------------------------------------------------- | ----------------------------------- | ------------------------------------------------------------------------------------------------------------------ | ------ |
| 文本（主字段）                                              | 单行，超出截断                      | 单击选中（强调色描边）→ 右上角出现「↗ 展开」看全量；Teable 是「点击即编辑、双击/空格展开」，飞书单击还是双击 `[C]` | 空白   |
| 单选 / 多选                                                 | 圆角胶囊标签，浅底 + 同色系深字     | 单击选中，再点开下拉                                                                                               | 空白   |
| 人员                                                        | 圆形头像（按人固定底色）+ 姓名      | 单击开选择器                                                                                                       | 空白   |
| 日期                                                        | `2023/06/11`，等宽数字              | 单击开日历浮层                                                                                                     | 空白   |
| 复选框                                                      | 勾选 = 对勾 + 文字                  | **单击直接切换**（无浮层）                                                                                         | 空方框 |
| 附件                                                        | 缩略图                              | 单击预览                                                                                                           | 空白   |
| 公式 / 查找引用 / 创建时间 / 最后更新时间 / 创建人 / 修改人 | 只读                                | **不可编辑**                                                                                                       | 空白   |
| 长文本                                                      | 单元格一行 + 「↗ 展开」，详情里全文 | 同上                                                                                                               | 空白   |

**「编辑不打断浏览」的实现方式**（最值得迁移的一点）：编辑在单元格 / 下拉浮层里**就地发生**，
表格不重排、不跳转；只有「一屏放不下的东西」（字段配置、记录详情）才升级成侧边面板；
**数据改动不需要保存动作**，只有视图级配置才有「清除 / 保存」。

## 4. 值得抄的原则（附「什么时候不该抄」）

| #   | 原则                                         | 理由                                           | 不该抄的情况                                                                  |
| --- | -------------------------------------------- | ---------------------------------------------- | ----------------------------------------------------------------------------- |
| 1   | 能就地编辑就不弹层                           | 弹层遮上下文、打断「扫一列」的节奏             | 需乐观锁 / 跨字段校验 / 动作不可逆（重置密码、批量退回）时必须显式确认        |
| 2   | 单元格只显示一个值，全量靠「展开」           | 靠加宽列换信息会把表越撑越宽                   | 该字段本身是筛选 / 对比依据时（学号、班级），定宽截断 + `title` 更好          |
| 3   | 悬停才出现的控件不参与布局，且必须有常驻替代 | 行悬停出现 `⋯` 但行不变高                      | 不可逆或低频动作（重置密码）：藏起来的发现成本 > 省下的宽度                   |
| 4   | 工具栏分左右两段：左「怎么看」，右「拿去用」 | 两半语义不同，混排会让人不知道点了会不会改数据 | 只有三四个按钮时不必强行分段                                                  |
| 5   | 密度是视图级设置                             | 录入的人要宽、扫描的人要窄                     | 单一固定用途的表（本项目成员表）没有多视图概念                                |
| 6   | 行高只调行，表头高度独立                     | 列名换行不该撑高每一行                         | 列名都很短时不需要                                                            |
| 7   | 列宽按内容分配                               | 平均分配会在窄列之间留大片空白                 | 用户手动调列宽在固定字段的后台里是负担（没地方存）                            |
| 8   | 首列冻结 + 行号列 = 横向滚动的身份锚点       | 没有锚点，横滚后不知道在看谁                   | 冻结列 + `border-collapse: collapse` 有已知渲染坑，实现前必须验证             |
| 9   | 空值就留白，不塞占位噪声                     | 视觉噪音最低                                   | 列多且定宽时空白分不清「没数据」与「没渲染」——本项目用 `—` 是有意为之，保留   |
| 10  | 批量入口常驻顶栏，未选中时禁用               | 没有出现 / 消失就没有位移                      | 需额外输入的批量动作（退回原因）应走弹层                                      |
| 11  | 颜色只表达分类，不表达重要程度               | 标签色按选项固定                               | **本项目不该抄配色**：设计系统只有一个强调色，没有 Success / Warning / Danger |

**看懂但不建议抄的机制**：视图级临时配置 +「清除 / 保存」；4 档行高与自适应行高
（行高随内容变化直接违反「操作前后其它像素不该移动」）；首列不可删 / 不可移。

## 5. 映射到本项目（成员表）

**直接可用的（零 / 低后端成本）**

1. 新增「技能标签」列：`MemberListEntry.skills`（随列表一次取出）→ 已实现。
2. 新增「加入时间」列：`joinedAt` 本来就在列表契约里 → 已实现。
3. 昵称从「同行标签」改成姓名下的第二行小字 → 已实现。
4. 数字 / 日期列右对齐 + `tabular-nums`；`班级` 截断 + `title` → 已实现。
5. `.admin-table-wrap` 开横向滚动，列多时不压缩列宽 → 已实现。

**建议但要单独立项**

- **首列冻结**（`position: sticky; inset-inline-start: 0`）：需要不透明底色 +
  `border-collapse` 下的边框验证，属于新增稳定视觉模式。
- **详情窗口的上一条 / 下一条**：`MemberAdminPanel` 把 `items` 与 `detailId` 一起传进窗口，
  写操作后按 `id` 重新定位（不要缓存 index）。收益：连续核对成员时不用「关窗 → 找行 → 点详情」。
- **表头排序**：要给 `/api/v1/admin/members` 加 `sort` 参数并贯通 Service / Repository /
  测试 / 文档，属 API 变更。
- **行高密度档位**：需要偏好存储（用 `localStorage`，不引依赖），但优先级低。

**明确不做**：不把 `.admin-modal` 改成右侧抽屉（它是公共组件，且 <760px 已经铺满高度，
居中窗口并非缺点）；不在列表末尾加「＋ 新增成员」（无限下翻会把末尾内容不断推走，
正撞「随内容出现的东西会让布局位移」这条禁令）。
